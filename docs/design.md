# OpenSerial Design Guide

本文档用于定义 `OpenSerial` 的界面设计原则、视觉基线、布局策略和 Pencil 原型约束。

目标是保证这个项目在持续由 AI 参与设计和实现时，UI 仍然保持统一、克制、可长期使用，而不是逐步变成风格混乱的拼装界面。

## 1. 设计目标

OpenSerial 的界面不是营销产品，不追求夸张视觉表现。

它的核心目标是：

- 清晰
- 稳定
- 耐看
- 高信息密度但不压迫
- 适合长时间盯日志
- 适合嵌入式调试工作流

## 2. 风格定位

关键词：

- 简约
- 低饱和
- 专业
- 冷静
- 技术感
- 不炫技

不采用的方向：

- 霓虹风
- 游戏风
- 彩色仪表盘风
- 渐变堆砌风
- 强动效展示风

## 3. 视觉原则

### 3.1 颜色克制

- 主界面以中性色为主
- 功能分区依赖层级、留白和边界，不依赖大面积高饱和块面
- 状态色只在必要时出现
- 红黄绿都要降饱和，避免刺眼

### 3.2 信息优先

- 日志内容是核心信息，不应被装饰元素抢走注意力
- 控件视觉权重低于日志内容
- 过滤和解析面板要清晰，但不能压过主日志区

### 3.3 长时间可读

- 保证文本对比度
- 避免纯黑纯白的大面积强对比
- 避免高频闪烁和无意义动画
- 避免多颜色同时竞争注意力

## 4. 色彩建议

建议采用低饱和中性调色板。

### 主色板建议

- 背景：浅灰白、暖灰白、雾白
- 面板：柔和灰、浅石墨、冷灰
- 文本主色：深石墨
- 文本辅色：中灰
- 边框：低对比浅灰线
- 强调色：雾蓝或冷灰蓝

### 状态色建议

- 成功：低饱和灰绿
- 警告：低饱和土黄
- 错误：低饱和砖红
- 信息：低饱和雾蓝

### 避免

- 纯亮蓝
- 荧光绿
- 纯正高亮红
- 大面积紫色或霓虹渐变

## 5. 字体建议

界面建议使用两类字体：

### UI 正文字体

建议：

- Geist
- Inter
- SF Pro 类风格替代

要求：

- 清晰
- 中性
- 适合高频信息阅读

### 数据 / 日志字体

建议：

- IBM Plex Mono
- JetBrains Mono
- Geist Mono

要求：

- 数字清晰
- 字宽稳定
- 适合日志、时间戳、HEX、字段对齐

## 6. 布局原则

### 6.1 主日志区必须居中成为核心区域

首版界面中，最重要的视觉区域永远是日志流。

建议比例：

- 左侧连接区：窄
- 中间日志区：宽
- 右侧分析区：中等，可收起

### 6.2 首版推荐布局

```text
+--------------------------------------------------------------+
| Top Toolbar                                                  |
+-----------+--------------------------------+-----------------+
| Left Pane | Main Log Stream                | Right Pane      |
|           |                                |                 |
|           |                                |                 |
+-----------+--------------------------------+-----------------+
| Send Panel                                                   |
+--------------------------------------------------------------+
```

区域说明：

- 顶部：连接、会话、导出、显示模式
- 左侧：端口与参数配置
- 中间：日志流
- 右侧：过滤、搜索、解析、状态视图
- 底部：发送区与历史命令

### 6.3 渐进式复杂度

默认界面只展示高频能力：

- 连接
- 日志
- 搜索
- 基础发送

增强能力按需展开：

- 高级过滤
- 自动波特率探测
- 规则解析
- 状态面板

## 7. 组件设计原则

### 7.1 按钮

- 主按钮数量要少
- 大多数按钮使用低存在感样式
- 只有“打开串口”“发送”等核心动作可以有更明显强调

### 7.2 输入框

- 形态简洁
- 边框细
- 避免重阴影
- 发送输入框要清晰但不抢视觉中心

### 7.3 标签与状态块

- 用于方向、级别、状态标识
- 色彩弱化
- 优先通过排版和边框区分

### 7.4 面板

- 面板边界清晰但不要厚重
- 尽量使用浅边框、极轻背景差
- 不要所有区域都套厚卡片

## 8. 日志区设计规范

日志区是本项目最重要的界面模块。

### 必须支持的视觉元素

- 时间戳
- 收 / 发方向标识
- 文本内容
- 搜索高亮
- 过滤后的可见状态

### 设计要求

- 单行结构清楚
- 支持高密度浏览
- 不靠鲜艳颜色区分所有状态
- 支持等宽字体
- 行高适中，避免挤压感

### 建议的视觉区分方式

- 时间戳用较弱颜色
- 方向标签用轻量色块或边框标签
- 正文保持最高可读性
- 匹配高亮用克制背景强调

## 9. 过滤与搜索区设计规范

过滤和搜索需要强功能感，但不能像表单后台一样笨重。

建议：

- 搜索框置顶
- 常用过滤项优先可见
- 高级过滤折叠进入
- 搜索命中数明确展示
- 过滤规则列表支持快速开关

避免：

- 一开始展开十几个过滤项
- 大量彩色 tag 堆满右侧
- 搜索和过滤入口分散

## 10. 上位机化面板规范

状态可视化面板必须建立在“有意义”的解析结果之上。

建议包含：

- 状态灯
- 当前模式
- 错误计数
- 最近关键事件
- 关键变量卡片

表现原则：

- 信息块尽量简洁
- 优先显示状态和变化
- 不做夸张的仪表盘
- 不为了“像工业软件”而堆复杂边框

## 11. 动效原则

动效只在必要时使用。

允许：

- 面板展开收起
- 搜索定位轻微反馈
- 状态变更轻微过渡

避免：

- 大面积漂浮动画
- 高亮闪烁
- 复杂入场动效
- 与日志刷新抢注意力的效果

## 12. Pencil 使用规范

Pencil 在本项目中用于：

- 信息架构探索
- 关键页面原型
- 布局比例验证
- 前端落地前对界面结构对齐

### 原型阶段建议

1. 先做低保真框架
2. 再做中保真主界面
3. 最后补状态色、标签和关键组件规则

### Pencil 输出建议

优先产出这些页面：

- 主工作台
- 高级过滤面板
- 日志解析 / 状态面板
- 设置页

### Pencil 设计要求

- 布局先行
- 装饰最少
- 通过留白和层级组织信息
- 保持组件命名清晰

## 13. 响应式策略

虽然项目主要是桌面端，但仍要考虑不同窗口宽度。

### 宽屏

- 三栏布局完整展开

### 中等宽度

- 右侧分析区可折叠
- 左侧连接区压缩

### 窄窗口

- 以中间日志区优先
- 两侧区域切换为抽屉或标签页

原则：

- 无论窗口如何变化，日志区不能失去主体地位

## 14. 可访问性与可用性

即使这是开发工具，也不应忽视基本可用性。

要求：

- 文本对比度充分
- 点击区域不要过小
- 键盘操作路径清晰
- 高频动作有快捷键预留
- 错误提示清楚

## 15. AI 实现约束

后续由 AI 生成前端代码时，应遵守以下约束：

- 不自动引入高饱和主题
- 不默认加重阴影、渐变、玻璃效果
- 不生成“营销感”布局
- 不把每个区域都做成厚重卡片
- 不让状态色泛滥

优先生成：

- 清楚的结构
- 稳定的层级
- 低干扰视觉
- 强可读性界面

## 16. 首版设计检查清单

每次做完一个界面，都至少检查：

1. 日志区是否仍是主视觉中心
2. 颜色是否过于鲜艳
3. 控件是否比内容更抢眼
4. 布局是否利于连续工作
5. 搜索和过滤是否一眼可达
6. 是否存在无意义的装饰
7. 是否符合“简约、低饱和、专业”的目标

## 17. 当前设计结论

目前已确认的设计方向：

- 简约风
- 低饱和
- 以中性色和雾蓝系为主
- 主日志区优先
- 可逐步扩展为轻量上位机
- Pencil 作为主要原型工具

后续所有 UI 方案都应以上述结论为约束。
